# 権限の仕組み（役割 × 対象 × グループ）

## なぜ変えるか
今は部署と役割（config/roles.json の5つ）で決めているが、同じ部署の中にも特権を持つ人とそうでない人がいる。また、部署をまたぐグループに専用で公開したいものがある。将来は IaC（クラウドの構成を読み取り・変更する機能）など、どのシステム・サーバーに接続してよいかを決める権限も要る。

## 要素
| 要素 | 中身 |
| --- | --- |
| 権限 | できる操作の最小単位。コード（yanua/permissions.py）で決める。画面からは増やせない |
| 役割 | 権限の束。データとして持つ |
| 対象 | 権限が効く先。種類は 部署・グループ・機能・システム・サーバー。まとめて名前を付けられる（対象のまとまり）。特別な対象として「メンバー自身の部署」と「全社」 |
| グループ | 役割 × 対象 を受け取る単位。権限は人に直接は与えない。入れ子は作らない |
| アカウント | グループのメンバー。人とシステムの2種類。メンバーには期限を付けられる |
| 文書・データ | 公開先（部署やグループ）と、見るのに要る権限を持つ（文書側は S-50 で作る） |

判定：その対象に対して、要る権限を持つグループに入っているときだけ、見られる・できる。

## 決まり
- システムアカウントは画面にログインしない（鍵やトークンで API だけ）。
- 権限を変えられるのは roles.assign を持つ人だけ。変更はすべて監査ログに中身つきで残す（断ったときも「拒否」で残す）。
- 自分の権限が増える変更はできない：自分が入っているグループに役割や対象を足す、自分をグループに入れる、自分の期限を延ばす（期限なしにするのも含む）、自分のグループが使っている役割に権限を足す。
- 権限が減る変更と、自分に効かない変更はできる（例：全員が入る「社員」のグループから役割を外す、ほかのグループを変える）。
- roles.assign を持つ人が1人もいなくなる変更はできない（締め出しを防ぐ）。
- 決まり（全員・部署）で入るグループは、メンバーを手で出し入れできない。中身（役割・対象）は上の決まりの範囲で変えられる。決まりの人に加えて個別の人も入れたいときは、別のグループ（例「総務（個別）」）にする。
- 期限が来たメンバーは自動で外れる。
- それでもだれも権限を戻せなくなったときは、サーバーに入れる人が復旧用のコマンド（python -m yanua access）で戻す。コマンドには「自分」がいないので自分の権限の決まりは当てないが、実行したことは必ず監査ログに残す（した人は「サーバーの操作」と OS ユーザー）。
- 将来、SSO（K-008）で AD・Entra ID のグループと対応づける。
- 接続情報（鍵）は対象の側に参照名として置き、グループや人には渡さない（IaC のとき）。

## 役割と既定のグループ
| 役割 | 中身の権限 | 既定のグループと対象 | 今 |
| --- | --- | --- | --- |
| 社員 | ask、search、documents.view、helpdesk、notifications、jobs.own、meetings、visits.own | 「社員」（全員）× メンバー自身の部署 | あり |
| 総務 | paper、paper.rules、visits.all、reception.records | 「総務」× 全社 | あり |
| ヘルプデスク担当 | helpdesk.handle（jobs.all は入れない。今の「情シス」はほかの人のジョブを見られないので、今の動きを変えない） | 「情シス・ヘルプデスク」× 全社 | あり（今の「情シス」） |
| 人事 | hr.view、hr.import | 「人事」× 全社 | あり |
| 文書管理 | documents.manage | 各部署の文書担当グループ × その部署 | 新規 |
| 管理者 | settings.*、network.*、kiosk.devices、roles.view、roles.assign、jobs.all | 「管理者」× 全社。今の動きを変えないため、「管理者」のグループには「監査」と「文書管理」の役割も与える（今の管理者は audit.view と documents.ingest を持っている） | あり |
| 監査 | audit.view、roles.view | 「監査」× 全社 | 新規（今は管理者に含まれる） |
| インフラ技術者・承認者・実行者・管理 | infra の各権限（依頼・承認・実行を別の役割に分ける） | どのグループにも与えない（将来） | 新規 |

システムアカウント（画面には入らない）：受付端末（/api/kiosk/ だけ）、更新の確認（S-53 の予定で見に行く）、IaC の実行役（将来）。
